# RemoteHand System Monitor v0.1.0 Design

Status: **Frozen implementation target**

## Goal

Deliver a useful Windows-first local system monitor while preserving a cross-platform provider architecture. RemoteHand core remains generic; System Monitor owns hardware detection, sampling, thresholds, history, alerts, CSV formatting, and presentation.

## v0.1 metrics

Required:
- overall CPU utilization
- per-logical-core CPU utilization
- memory used
- memory total
- memory available
- memory utilization percentage

CPU temperature is deferred beyond v0.1. The v0.1 package must not require .NET, PawnIO, a separately installed hardware-monitoring tool, or any third-party driver/runtime solely for temperature telemetry.

## Sampling and history

- default sample interval: 2 seconds
- retained in-memory history: 60 minutes
- graph/table windows: 5, 15, 30, 60 minutes
- default visible window: 15 minutes
- no persistent telemetry history in v0.1
- settings persist through RemoteHand plugin-scoped storage

At 2-second sampling the maximum 60-minute history is 1,800 samples.

## Main panel

The main page is intentionally focused:

- live CPU utilization graph
- live memory utilization graph
- per-core activity
- current/min/average/max metrics table
- selectable 5/15/30/60-minute window
- CSV export of the retained samples in the selected window
- settings for CPU/memory top-bar/tray visibility, health thresholds, colors, sound, and notifications

## Top bar

System Monitor may publish CPU and memory widgets through RemoteHand's generic top-bar API.

Each enabled widget may show:
- current value
- 1-minute sparkline
- tooltip with current details
- open-panel action

Each sparkline sample carries its own threshold-derived color. Healthy samples remain healthy-colored even when a later sample enters warning or critical state; only the samples that crossed those thresholds change color.

The plugin owns metric selection, threshold semantics, coloring, and formatting.

## System tray

Each metric may independently be enabled in the system tray.

A tray tile may publish:
- short live label/value, e.g. 70
- foreground/text color
- health-state background color
- border color
- tooltip
- open-panel action

CPU and memory thresholds and colors are user configurable.

Default CPU thresholds:
- healthy maximum: 70%
- critical minimum: 95%

Default memory thresholds:
- healthy maximum: 70%
- critical minimum: 90%

RemoteHand core only renders a generic short tray label; it does not understand CPU, temperature, RAM, or threshold semantics.

## Alerts

Each monitored surface supports independent:
- Sound
- Notification

Alerts are state-transition based. Remaining in the same warning/critical state does not retrigger every sample. A metric must leave the state before the same transition can fire again.

v0.1 should avoid threshold flapping by requiring two consecutive samples in a new state before committing the transition.

Native notifications use RemoteHand's generic notification API and open System Monitor when clicked.

## Provider boundary

```text
System Monitor UI
        |
Normalized SystemSnapshot
        |
Sampler / rolling history
        |
SystemProvider
        |
WindowsSystemProvider   <- v0.1
LinuxSystemProvider     <- later
GPU providers           <- later
```

The UI never reads Windows APIs directly.

## CSV

CSV export represents sampled telemetry, not only the summary table.

Initial columns:
- timestamp
- cpu_percent
- memory_percent
- memory_used_bytes
- memory_available_bytes
- memory_total_bytes
- core_0_percent ... core_N_percent

CSV destination selection uses RemoteHand's generic native Save As capability.

The suggested filename uses local time:

```text
system-monitor-history-YYYY-MM-DD-HHmm.csv
```

## Explicit non-goals

Not in v0.1:
- NVIDIA GPU monitoring
- Intel GPU monitoring
- AMD GPU monitoring
- Linux implementation
- fan control
- voltage/tuning/overclocking
- process manager
- benchmarking/stress testing
- persistent telemetry database
- motherboard-wide sensor-suite replacement
- CPU temperature provider / third-party hardware-access dependency

## Acceptance criteria

On the Windows 11 validation machine:
1. Plugin installs and starts without modifying existing RemoteHand data.
2. CPU overall/per-core utilization updates every ~2 seconds.
3. Memory metrics update every ~2 seconds.
4. 5/15/30/60-minute views work from the same retained history.
5. Main graphs and summary table update without requiring panel reload.
6. CSV export opens native Save As and produces parseable sampled telemetry.
7. Enabled CPU/memory top-bar widgets update with a one-minute sparkline.
8. Enabled CPU/memory tray tiles display a short live value and threshold-derived background color.
9. Tray/notification click opens System Monitor.
10. Warning/critical transitions do not alert every sample.
11. Existing plugins continue to render their tray graphs unchanged when no tray label is supplied.
12. The packaged plugin runs without requiring .NET, PawnIO, or another separately installed hardware-monitoring dependency.
13. Top-bar sparklines color each sample independently according to that sample's threshold state.
14. Alert state changes require two consecutive samples before sound or notification delivery.
15. Settings survive a full RemoteHand restart.
